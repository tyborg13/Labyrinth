## Requirements and contract

1. **Committed inputs.** `rr12_inputs.py` verifies 33 Grub / 41 Tick required
   delivery files against their committed capture manifests, including every
   label's solo, both part/clay maps and projected joints. All four registration
   sources pass. Both cases contain a byte-identical copy of the entire protected
   `spec/peer_benchmark/staged/rr-12/motion_tracks.json`. Source art, measurements
   and director files were read and copied, never edited. Every source view,
   part/clay map and solo was inspected, as were all feature outline crops.
2. **Rigid rigs.** Visible ownership comes from categorical flat interiors
   supported by native solos. Hidden requests and fill provenance are retained.
   Sparse occluded legs use the existing same-part, approved paired-view donor
   fallback; no unrelated material or new artwork is supplied. All physical
   crops are connected; hidden fills and seam underlays pass. Both rigs use the
   minimum passing support margin, zero. Both views of both cases reconstruct
   the approved processed RGBA with **0 differing pixels**. Native rest remains
   director-owned. Director `body` channels bind to the shared runtime's `root`.
   Grub chains outward from `seg_3`, with inter-ring meeting pivots derived from
   neighbouring native centres; legs retain their native ring attachments.
   Tick uses `shell > upper > lower`, and `shell > head`. Derived pivots and their
   native sources are recorded in each `rig_recipe.json`.
3. **Whole features.** One owner and one node per connected feature, a one-pixel
   rim, bounded holes filled, source RGBA unchanged. The rear maw is explicitly
   occluded. Each view's Tick cracks are separate painted surfaces with explicit
   per-view declarations, rather than invented front/rear correspondences.
4. **Production.** Both `assets/units/*_cutout/` directories contain production
   paint, layouts, features, seams, motion and runtime adapters. Board,
   pre-battle, inspection and turn portraits share the renderer. Exact staged
   selectors drive `gnaw:move_toward -> move`, `gnaw:melee -> gnaw`,
   `burrow:burrow -> burrow`, `erupt:erupt -> erupt`,
   `scuttle:move_toward -> move`, `scuttle:melee -> bite`, and
   `kindle:kindle -> kindle`. Existing death/burst and hit paths use the authored
   clips. Presentation normalizes the existing Kindle status snapshot to its
   authored selector. Burrow hands over to the existing mound only at completion;
   erupt starts at zero alpha on the resolved marked landing and starts existing
   dust, surface feedback and earth sound at contact. Kindle's existing effect
   and bonus snapshot start at contact. Resolver rules, balance, data, sounds,
   saves and analytics are unchanged. Existing melee sound/VFX boundaries map to
   clip contact. No engine/mechanics changes were necessary.
5. **Gates.** Independent signed-bone checks cover authored keys, midpoints and
   contacts in both views: 460 Grub / 168 Tick poses. Sequential 60 Hz pixel
   sampling covers 828 / 564 poses, including every clip and death. Feature
   integrity, connected parts, seams, exposed derived dark slabs and strict
   stray-component gates pass. Held-frame and boundary unexplained shimmer
   residuals are both zero. Mutations cover compiler signs, applied bones,
   omitted contacts/actions, transparent feature masks, frozen motion and
   detached components of every size 1–8. Native agreement retains rr-05/rr-07
   exact-tie handling, but new native acceptance awaits director captures.

Contract acceptance 1 (shared renderer and exact clips) has headless runtime,
surface and real-callback proof. Acceptance 2 has exact offline rest and all
headless gate proof; its native portion remains pending. The director's MP4,
contact-sheet and inbox inspection expectations remain director-owned.
