## Change (director decisions; exact)
1. **Coalesce.** Hover enter and leave no longer run `_refresh_stage_view`, `_refresh_turn_order_bar` or the tutorial refresh synchronously. They record the new hovered index and request one flush per frame, run deferred at the end of the current frame's input handling, before the frame draws. A leave and an enter in one frame produce exactly one flush, from the final state. The flush and the existing deferred hover refresh become one pass, so no stage refresh runs twice for one hover change.
2. **Nothing a player sees changes,** apart from frames arriving sooner: same final card emphasis, previews, glossary, strip and tutorial state as before, drawn on the same frame as before (no frame of latency added; prove it). A click, drag start, key press, Pass or anything else that reads hover state in the same frame must see the current state: flush first at those entry points when one is pending. The existing `_updating_hand_interactions`, `_hand_hover_refresh_pending`, `_animation_lock`, `_player_movement_selected`, `_selected_card_index`, `_card_action_choice_index` and `_drag_card_index` guards keep their meanings.
3. **A sweep workload.** Add an option to `tools/perf11_soak.gd`, off by default: `--hand-sweep`. Each hover phase slides across the whole hand, firing leave then enter in one frame for each adjacent pair, with no board target. The default workloads stay byte-identical. Report sweep frames as their own phase.
4. **Equivalence proof,** on demand, like perf-11's `movement_equivalence.gd`: over a scripted sequence (enter, enter another, leave, leave plus enter in one frame, enter during `_animation_lock`, enter then click in one frame, enter then drag, enter then Pass, enter with the tutorial active), compare the final state to the original scene's as a reference (generated by `perf11_proof.py`, as its oracle does): emphasis index, preview dictionaries, glossary content, strip order. Also report refresh counts per frame, before and after: the target is 1.
5. **Report the CPU numbers** from `perf11_soak.gd` headless, before and after, as perf-11 did: `hand_enter`, `hand_leave`, and the sweep's frames. Say what stage work still runs and how many ms remain.
