# ev-01 — Data-driven event engine and omens (rules, save, headless; stopgap UI)

## Header
- Goal: every "event" room plays a different authored event from `data/events.json` (27 events) with real trade-offs,
  instead of the single hardcoded Lost Cartographer; events can grant/cost HP, max HP, Embers, relics, magic cards,
  gear, items, Defiance, Scouts, route reveals, and timed **omens** (blessings/banes lasting N fights).
- Base: `codex/peer-benchmark` (integration branch). Depends on: nothing.
- Docs to read (sections only): spec/section_map.md "Discovery and decisions" (Lost Cartographer) and "Saves, recovery and
  analytics"; spec/analytics.md (map events); spec/item_relic_rules.md headers; spec/turn_clock.md "Scheduling" (for
  first-turn play/movement hooks); AGENTS.md (Windows typed arrays; analytics; hotspot rule).
- Owned files/dirs (create/modify only these):
  - new: `scripts/event_rules.gd`, `scripts/omen_rules.gd`, `tests/suites/event_rules_suite.gd`, `tests/event_rules_test.gd`,
    `spec/events.md`
  - `data/events.json` (director-authored, already committed — see Data provided; do not edit its content)
  - `scripts/run_engine.gd` (event entry/resolution, omen tick, effect application helpers — keep additions small; put
    logic in event_rules.gd/omen_rules.gd)
  - `scripts/combat_engine.gd` (omen hooks in combat creation, first activation, ember drops — minimal)
  - `scripts/room_generator.gd` (extra enemy for the Hunted omen only)
  - `scripts/game_data.gd` (events/omens loader + accessors only)
  - `scripts/section_map_panel.gd` (ONLY `_build_event` and its refresh path: make the existing event panel data-driven —
    see Change 9; no other panel edits)
  - `tools/headless_playtest.gd` (event commands)
  - `spec/analytics.md`, `spec/section_map.md` (event paragraphs only)
  - `tests/suites/section_map_suite.gd` (only to update Lost Cartographer expectations if the new engine changes them)
- Rules: Windows `Array[T]` rule; no growth of `scripts/run_scene.gd` beyond wiring calls (≤ 30 lines) — prefer zero;
  no new art or audio; every player-facing string comes from `data/events.json` or the exact templates in this brief;
  `TODO_DESIGN_<name>` for anything undecided.
- Contract: risk tier **high** (saves, reward flow, combat creation). Acceptance: (1) event rooms resolve a seeded,
  unseen, section-appropriate event; (2) every effect/requirement type works and is unit-tested; (3) omens apply at combat
  start and tick down per finished combat; (4) mid-event save/load and legacy Lost Cartographer saves resume; (5) analytics
  record event id, choice id and resolved outcomes. Proof: new event_rules suite, section_map suite, full Godot suite.
  Inspection: playable via a fixture (director runs it).

## Change (numbered, testable)
1. **Loader.** `GameData.events()` / `GameData.event_def(id)` / `GameData.omen_def(id)` load `data/events.json` once
   (same caching style as the other data files). A validation function `EventRules.validate_data() -> Array[String]`
   returns problems; the suite asserts it is empty. Validation rules: every event has title, body (≤ 70 words), pool in
   {any, earth, fire, air, ice, lightning, shadow}, 0 ≤ min_section ≤ max_section ≤ 5, weight > 0, 2–3 choices with unique
   ids and labels ≤ 28 characters; every effect/requirement type is one listed below; random outcome weights sum to
   100; every omen id referenced exists; every omen has name, kind ∈ {blessing, bane}, fights ≥ 1, description and a
   known effect type. `art_path` is NOT in the data yet: derive it as `res://assets/art/events/<event_id>.png` in one
   accessor (`EventRules.art_path(id)`); missing files are allowed (UI falls back).
2. **Selection.** On first entry to an `event` room, pick and persist `room["event_id"]`:
   - Section element = the section boss's element (`DragonBossLibrary.element_for_boss`; Noctyrax → `shadow`).
   - Candidates: pool == "any" or pool == section element, section index within [min_section, max_section], not in
     `run_state["seen_events"]`. Weighted pick with an RNG seeded from run seed + room coord (deterministic, independent
     of iteration order of dictionaries — sort ids first).
   - Fallbacks in order: any unseen event of pool "any" ignoring section bounds; then `lost_cartographer`.
   - Append to `seen_events` when the event is resolved (not on entry), so a save/load before choosing re-offers the
     same event (the persisted `event_id` guarantees that).
   - Legacy saves already in an event room without `event_id` resolve as `lost_cartographer` (choice ids `embers` and
     `survey` are preserved in the data for this reason).
3. **Event state.** While in an event: `run_state["mode"] == "event"` and `run_state["event_state"] = {event_id, page:
   "choices"|"result", choice_id, result_text, outcomes: Array[Dictionary]}`. Choosing applies effects atomically, sets
   page "result" with the choice's `result` text (or the picked random outcome's `result`, or empty → UI shows none), and
   `outcomes` lists the concrete results (e.g. `{"type":"relic","id":"iron_lung"}`, `{"type":"hp","amount":-5}`,
   `{"type":"omen","id":"hunted","fights":2}`). `EventRules.continue_event(run_state)` finishes: clears the room,
   `mode` back to `room` (or opens the card choice, Change 6), and the existing map-reopen behaviour after an event still
   applies. Save/load works on both pages.
4. **Requirements** (choice disabled when unmet; disabled choices stay listed): `hp_above{amount}` (current HP >
   amount), `max_hp_above{amount}`, `embers_at_least{amount}` (held Embers), `has_item` (any consumable in pack or
   equipped items), `has_equipment{slot}` (an equipped piece in that slot), `has_attuned_magic` (≥ 1 attuned magic card).
   `EventRules.choice_available(run_state, event_id, choice_id) -> bool` and `choice_block_reason(...) -> String` with
   exact reasons: "Requires more than N Health." / "Requires more than N max Health." / "Requires N Embers." /
   "Requires an item." / "Requires an equipped <slot name>." / "Requires an attuned spell." (`<slot name>`: weapon,
   offhand, armour, boots, trinket).
5. **Effects** (apply in listed order within a choice):
   - `hp{amount}`: negative never takes HP below 1. `heal{amount}`: capped at max HP. `heal_percent{percent}`:
     round(max_hp × percent / 100), capped.
   - `max_hp{amount}`: change `player_max_hp`; positive also raises current HP by the same amount; negative clamps current
     HP to the new max; max HP never below 1.
   - `embers{amount}`: through `add_held_embers` / `spend_held_embers` (same unbanked/held semantics as Lost Cartographer).
   - `relic{rarity}`: random relic of that rarity from the treasure-offerable pool not owned (same eligibility as
     `_generate_relic_choices`; never guardian/dragon exclusives). If none: next lower rarity, then any offerable; if the
     pool is empty, grant 40 Embers instead (outcome records the substitution). Max-HP relic bonus applies exactly like
     `claim_relic`.
   - `card{rarity, element}`: random reward-pool magic card; `element` = "section" (section element; shadow → any),
     "any", or an element id. Goes to the magic reserve exactly like a claimed card reward (marks NEW/unread).
   - `card_choice{count, element, min_rarity?}`: generate `count` distinct reward-pool magic cards (element as above;
     rarity weights as card rewards but never below `min_rarity`) and present them after the result page (Change 6).
   - `equipment{rarity, slot?}`: random equipment piece of that rarity (and slot if given) not already owned; falls back to
     lower rarity then any rarity; to the pack like a Scavenger purchase (NEW/unread). Empty pool → 40 Embers.
   - `reforge{slot, rarity_step}`: replace the equipped piece in `slot` with a random different piece of the same slot at
     rarity + step (capped at legendary). The old piece and its grafts are destroyed (not returned to the pack); the new
     piece is equipped in the same slot and the deck is rebuilt.
   - `item{count}`: random consumable item cards into the item pack (use the same acquisition path as board pickups /
     Scavenger; respect existing pack rules).
   - `lose_item`: remove one random consumable (pack first, then equipped items).
   - `transform_magic{count, rarity_step}`: replace `count` random attuned magic cards (fewer if fewer attuned) each with
     a random different reward-pool magic card of rarity + step (capped at legendary), any element; the replacement takes
     the same attuned slot; record from→to in outcomes.
   - `omen{id}`: add omen (Change 7).
   - `defiance{amount}`: +amount Defiance charges usable this run only (add capacity and remaining for this run; never
     persisted to progression).
   - `scout{amount}`: +amount Scout uses for the current section.
   - `reveal{hops}`: exactly the existing Lost Cartographer survey (descendants up to `hops`); a choice whose ONLY effect is
     a reveal is unavailable when nothing new would be revealed ("Nothing new to reveal.").
   - `random{outcomes}`: seeded pick (run seed + room coord + choice id) among outcomes by weight; applies that outcome's
     effects and result text.
6. **Card choice from events.** After Continue on a result page that granted `card_choice`, present the existing card
   reward chooser with those cards. Skipping grants nothing (no heal) and the skip button reads "Skip". Claiming puts the
   card in the reserve exactly like a combat reward. Then return to the room (event room cleared) and the map flow resumes.
   Reuse the existing reward state/flow; do not build new UI.
7. **Omens** (`scripts/omen_rules.gd`). `run_state["omens"]: Array[Dictionary]` of `{id, fights_left}`. Adding an omen
   that is already active sets `fights_left = max(current, def.fights)` (no stacking). After every finished combat
   (victory, escape, or Last Door retreat; including guardian and boss fights) decrement all, remove at 0. Effects, read
   from `omen.effect` at combat creation:
   - `start_block{amount}`, `start_stoneskin{amount}`: added to the player's starting Block/Stoneskin.
   - `start_expose{amount}`: player starts with Expose = amount (next hit against the player deals +amount; implement for the
     player if only enemies support it today).
   - `start_vision_turns{amount}`: player starts with the existing Vision status for amount turns.
   - `first_turn_card_plays{amount}`, `first_turn_movement{amount}`: modify only the player's first activation of the combat
     (plays never below 1, movement never below 0). Wait cost (turn_clock.md) counts unused BASE plays only; a bonus
     omen play never waits.
   - `start_on_fire`: create the Fire surface on the player's start tile at combat start if that tile can hold Fire.
   - `umbra_stage_delta{amount}`: the room's starting Umbra stage moves amount stages deeper (never to the boss-only
     Eclipse stage).
   - `ember_drop_percent{amount}`: enemy `reward_embers` × amount/100, rounded half up; multiple omens multiply.
   - `extra_enemies{amount}`: standard combat rooms only (never guardian/boss); add enemies drawn from the room's normal
     pool for its depth/element at legal free tiles when the layout is generated; the pre-battle dossier shows them
     because they are in the layout.
   `OmenRules.active(run_state) -> Array[Dictionary]` (id, name, kind, description, fights_left) for UI later.
8. **Preview strings.** `EventRules.choice_effect_lines(run_state, event_id, choice_id) -> Array[String]`, one line per
   effect, exact templates (inline icons use the existing `@icon(name)` markup; an icon is never glued to letters):
   - hp −N: "Lose N @icon(health)." · heal N: "Heal N @icon(health)." · heal_percent P: "Heal P% of your max @icon(health)."
   - max_hp +N: "+N max @icon(health)." · max_hp −N: "−N max @icon(health)." (U+2212 minus)
   - embers +N: "Gain N Embers." · embers −N: "Pay N Embers."
   - relic: "Gain a random <Rarity> relic." (Rarity capitalised: Common, Rare, Epic, Legendary)
   - card: "Gain a random <Rarity> <Element> spell." (Element omitted when any; "section" resolves to the section element
     name, capitalised: Fire, Ice, Lightning, Earth, Air)
   - card_choice: "Choose 1 of N <Element> spells." / with min_rarity: "Choose 1 of N <Element> spells, <Rarity> or better."
   - equipment: "Gain a random <Rarity> <slot name>." or without slot "Gain a random <Rarity> piece of gear."
   - reforge: "Reforge your <slot name> into a random <next Rarity> one."
   - item: "Gain a random item." / "Gain N random items." · lose_item: "Lose a random item."
   - transform_magic: step 0: "Transform N random spell(s)." with exact plural "Transform a random spell." /
     "Transform 3 random spells."; step 1: "Transform a random spell into a higher rarity."
   - omen: "<Blessing|Bane>: <Name>. <description> (<fights> fights)"
   - defiance: "Gain 1 @icon(defiance) for this run." · scout: "+N Scout." · reveal: "Reveal the routes up to N rooms ahead."
   - random: one line per outcome: "<weight>%: <its effect lines joined with a space>" and "<weight>%: Nothing." for an
     empty outcome.
   Tests assert the exact strings for at least: bloodletters_basin (both lines of "bleed" and both random lines of
   "reach"), ember_usurer.borrow, abandoned_forge.weapon, mirror_of_skins.trade.
9. **Stopgap UI (temporary until ev-02).** `section_map_panel.gd` `_build_event` renders the current event generically:
   title, body, one button per choice (label + effect lines joined by " "), disabled with the block reason as tooltip
   when unavailable; after choosing, the same panel shows the result text and outcomes, plus a "Continue" button. Keep
   the existing panel size/style; text may be small. No art. This is replaced by an illustrated view in ev-02.
10. **Analytics.** Extend the existing map event analytics: `map_event_resolved` gains additive fields `event_id`,
    `choice_id`, `outcomes`; add `omen_gained {id, fights}` and `omen_expired {id}` events through the same append-only
    outbox. Update spec/analytics.md.
11. **Headless console.** `event` lists the current event's choices with availability and effect lines;
    `event <choice_id>` chooses; `event continue` continues. Keep `event embers|survey` working for the Cartographer.
12. **Spec.** New `spec/events.md`: purpose, schema, selection, effects, omens, preview templates, save/analytics, how to
    add an event (data only). Trim the Lost Cartographer paragraphs in section_map.md to point there.
