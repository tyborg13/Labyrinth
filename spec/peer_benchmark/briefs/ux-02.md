# ux-02 — Player-facing text and tooltip audit (inventory only, no text changes)

## Header
- Owner, playtest 7 (2026-10-15): a broad cleanup of UI text so it is "really clean and crisp and easy for players to
  understand. A lot of our tooltips are either not enough information or too much information or too wordy ... there's
  some cases where we need tooltips but don't have them" (relic iconography on relic choice and owned relics has no
  explaining tooltip). The director will rewrite the text; this unit produces the complete, accurate inventory the
  rewrite needs.
- Base: `codex/peer-benchmark`. Owned files: new `tools/text_audit.py`, new `tests/text_audit_capture_probe.gd` (+ its
  proof contract), new `spec/peer_benchmark/staged/text/` outputs. Read-only everywhere else.
- Rules: change no game text, data or UI code. Real-renderer captures via SubViewport 1920×1080 at 100% UI scale.

## Change
1. **String inventory** → `spec/peer_benchmark/staged/text/inventory.json` (+ a CSV for spreadsheet review): every
   player-facing string with: stable id, surface (card name/rules/flavour, card tooltip, keyword tooltip, relic
   name/description, relic tooltip, status/condition tooltip, intent label/tooltip, enemy name/tooltip, event title/body/
   choice, map node, reward screen, shop, chronicle, run-end recap, menus/settings, HUD labels, onboarding/tutorial,
   confirmation dialogs, error/empty states), source (data path + key, or `file:line` for strings in code, including
   format strings with their parameters), the exact current text (with BBCode/markup and inline icon tokens kept),
   word count, how numbers are filled in (static, formatted from data, upgraded variant), where it is shown, and whether
   the string is shown in a tooltip, inline, or both.
2. **Icon inventory** → `inventory_icons.json`: every icon a player can see (inline icon tokens in card/relic/status text,
   intent icons, status icons, relic icons, map icons, HUD icons, chronicle icons): id, art path, every surface it
   appears on, the concept it stands for (from code), whether hovering/focusing it shows a tooltip on each surface
   (yes/no/partial), and the current tooltip text if any. Flag every surface where an icon carries meaning without a
   tooltip (the owner's relic case first).
3. **Keyword/concept glossary seed** → `glossary_seed.json`: every keyword, status, element, damage type, resource and
   icon concept with its current player-facing name(s) and every current definition text found in code/data (verbatim,
   with sources). Report naming inconsistencies (same concept, different names; same name, different concepts) and
   definitions that disagree with the rules code (cite the rules code).
4. **Captures**: a probe capturing every tooltip type and every text-heavy screen at 1920×1080 (card hover in hand,
   card reward, relic choice with a relic hovered, owned relic tray hovered, status hover, intent hover, map node hover,
   event, shop, chronicle, run-end recap, settings) into a numbered contact set, plus `captures.md` mapping capture →
   inventory ids. Use existing probes' fixtures where possible.
5. **Metrics** in `summary.md`: string counts per surface, longest strings per surface (top 15 by words), tooltips over
   35 words, cards whose rules text exceeds 3 lines at the card's font size, icons without tooltips per surface.

## Proof
`python3 tools/text_audit.py --check` (inventory reproducible from the tree, no unknown sources); the capture probe's
headless validation; list the exact windowed capture command for the director.

## Out of scope
Rewriting any text, adding tooltips, renaming anything (that is ux-03/ux-04 after the director's rewrite).
