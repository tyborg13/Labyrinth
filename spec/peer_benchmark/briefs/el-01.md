# el-01 — Battlefield rules: framework, the six resolvers, Wind becomes Gust

## Header
- Owner-approved design: `spec/peer_benchmark/element_rules/design.md` (binding; read all of it first). Owner
  principle: no one-off rules. Each rule is an existing primitive applied on a beat; fights differ only by data dials.
  If you find yourself writing a special case for one encounter, stop and report `TODO_DESIGN_<what>`.
- Base `codex/peer-benchmark`. Risk tier: standard.
- Owned:
  - new `scripts/battlefield_rules/` (one resolver per rule plus a small dispatcher);
  - new `data/battlefield_rules.json` (rule definitions: id, display name, icon key);
  - `scripts/enemy_mechanics/wind.gd` (migrated into the Gust rule; keep the file only as a thin adapter if callers
    still need it);
  - minimal hook points in `scripts/combat_engine.gd` (net-neutral or smaller where you replace Wind calls);
  - `data/glossary.json` (Wind → Gust entry only);
  - `spec/analytics.md` and the analytics emitter for the new event;
  - tests.
- Not owned: views, HUD, the turn-order HUD drawing, encounter data, Warband/Snare rules other than the Gust
  migration, enemy intents. Those are el-02 (content) and el-04 (director visuals).

## Change
1. **Framework (design §1).**
   - The rule instance in `combat_state.battlefield_rule`: an additive save field, with legacy saves loading as none.
   - Cadence anchors: `after_source_turn`, `after_player_turn`, `on_intent`.
   - Source death ends an enemy-sourced rule.
   - One dispatch point per anchor in the turn flow, replacing the per-enemy-turn Wind call in
     `BrambleRules.complete_turn` and the Snare's player-turn Wind call.
   - The beat entry in `current_turn_order` (`{kind: "beat", rule, at}`), placed after the turn that triggers it.
   - The pure `forecast(engine, state)` contract, using the real resolver on a copy.
   - The `battlefield_rule_fired` analytics event.
2. **The six resolvers (design §2),** each built only from existing engine primitives. Name the primitive you call in a
   comment beside each step.
   - **Gust:** reuse `Wind.push_all` unchanged. Direction modes: `aimed` (the existing announcement, locked),
     `toward_entry`, `fixed`. `toward_source` and `turn_clockwise` come later; build their enum entries only, and error
     if they're used.
   - **Wildfire:** snapshot the Fire tiles, then place Fire through the player cards' placement path. Spread modes:
     `toward_player` (locked one beat ahead and exposed in the forecast), `away_from_entry`, `all`. Also the `lasting`
     dial.
   - **Frostbite:** an Ice hit of `damage` on every unit on Ice, through the existing Ice-hit path (Chilled → Freeze,
     expend the Ice beneath).
   - **Lightning Storm:** the existing Lightning Strikes damage and Shock on every Electrified tile, without changing
     the field, plus the existing Chain from each unit hit when `chain > 0`.
   - **Upheaval:** marks one beat ahead by `pattern`, then raises Outcrops with `health` through the Raise Terrain path,
     displacing occupants through the Erupt displacement path. Build `line_between` (the existing
     `line3_perpendicular_front_of_hero` geometry, extended to `length`) and `exit_lane` (the existing Snare rubble-lane
     selection plus its never-seal-the-last-way guard). Leave the other patterns as enum entries that error.
   - **Shadowstep:** hidden-from-player enemies Blink toward the hero, as specified (landing selection, ordering,
     ground trigger, Umbra privacy).
3. **Wind becomes Gust.**
   - Every current Wind user runs through the framework with the design §3 rows: the Stormcaller (Warband order
     `stormcaller_wind`), the ordinary Gale Herald's Call the Wind, and the air Snare headwind.
   - Behaviour changes only where the design says so: pushes now fire `after_source_turn` (every 1) instead of after
     every enemy's turn. The Snare stays `after_player_turn`.
   - Keep `WindView`'s existing presentation working: ghosts, streams, push wave and chip. It may read from the
     framework's forecast. Don't redesign it; el-04 owns visuals.
   - Rename the Wind glossary entry to Gust. Its definition must say exactly: "The wind Pushes every unit 1 tile
     downwind on its beat. Anchored units don't move." It keeps the `wind` icon key (same concept).
4. **Panel sentence data.** Store the design §3 panel sentences verbatim as instance data (they are director text), and
   expose `panel(state) -> {rule, name, icon, sentence}` for the view. Only the Gust instances are live in this unit.

## Proof
- Headless unit tests per resolver on small fixed boards: one test per dial value, the forecast equal to the resolution,
  Anchored/Fireproof respected, a dead source ends the rule, save round-trip, the turn-order beat entry position, and
  the Umbra privacy of the Shadowstep forecast. Add a mutation per resolver guard.
- Existing suites that must stay green: en02_enemies, warband_orders, warband_ui, wbv_markers, snare, snare_ui,
  warband_orders_probe `--check-only`, card_keywords and full_scene_controls_program.
  - Tests that pinned "pushes after every enemy turn" are updated to the new cadence. List each one changed and why.
- Score nothing on the card heuristic. The cadence change is a director decision; el-02 measures encounter difficulty.
- No full suites; the director runs them at merge.

## Out of scope
Encounter retrofits (Slagmaster, Oracle, Dynamo, Thornmother, Prior, and the five other Snare pressures), the ordinary
enemy changes, keyword retirement and all visuals. Those are el-02 and el-04.
