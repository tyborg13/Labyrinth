# qa-16 whole-run hunt

This one-off tool plays `RunScene`, not the engine REPL or a fixture. Gameplay,
scene files, tuning, and assets are untouched. Findings are evidence for director
triage; the hunt does not fix them or install permanent regression guards.

Cold import, then the bounded campaign:

```sh
cd /Users/borgerding/workspace/Labyrinth.worktrees/qa-16 && LABYRINTH_CEL_LOOK=off python3 tools/godot_task_runner.py --task-id qa-16 --timeout 500 --stream -- godot --headless --path . --import
cd /Users/borgerding/workspace/Labyrinth.worktrees/qa-16 && LABYRINTH_CEL_LOOK=off python3 tools/run_hunt.py
```

The Python coordinator starts seeds 1, 2, 3, …, permits at most three concurrent
Godot processes, and stops launching at 75 minutes. Existing children drain under
their own watchdogs. Use a fresh `--output-dir` for every invocation. A single
seed can be replayed with `--seed N --runs 1 --processes 1 --stop-after N`; omit
`--stop-after` to play until termination. The report records exact replay commands.
The default invocation writes this directory's `report.md`, with raw per-seed
files under `campaign/`. A custom output directory contains its own report.
`--report-only --output-dir PATH` rebuilds that report from completed raw logs
without starting another Godot process.
`--include-evidence PATH/seed-N/evidence.json` adds a separately verified replay's
findings without adding its run count or rooms to the campaign coverage. The
report preserves that replay's script path from its original command metadata.

The driver uses the production New Run seed hook, input handlers, visible enabled
controls, legal previews, and board click paths. Health is set once through the
fixture's `player_max_hp` / `player_hp` fields, before the first decision. It is
never replenished by the driver. Tutorial Skip is a real offered button. Save
flushes the production committed boundary, destroys the scene, and re-instantiates
it with the same root resume metadata used by the menu. No snapshot is installed.

Each legal offer is sampled uniformly. In combat, 80% of draws first restrict to
attack cards/targets or movement that reduces Manhattan distance to a living
enemy, when any exist; the other 20% draw from all offers. Each side action gets
one independent 10% trial per room when first available. The terminal heirloom
view has no in-run open/close control; it is exercised as an offered terminal
choice when available. No substitute view is manufactured.

`trace.jsonl` flushes every decision and room census. The coordinator retains the
combined Godot output, every error/warning occurrence, source stack, current
context, and last 20 decisions. It deduplicates only by exact error text and file
location, then orders crash, softlock, script error, warning, leak. Startup and
shutdown markers are included. A nonzero runner exit is visible separately from
the original error, since the runner can convert a native zero exit to failure.

Fight screens have the 200-decision limit. Other screens have the 120-decision
limit, keyed by room, mode and event page. No offered decision while unlocked for
20 seconds of scene time is a softlock. An animation lock is never cleared by the
driver. The outer watchdog bounds a permanently locked or crashed driver.

Room entry records live tree nodes, total nodes, and orphan nodes. The first
section 5 entry is compared with the first section 0 entry; growth above 25% is
flagged, including any growth from a zero orphan baseline. No section 5 entry
means no completed leak comparison. Required and observed room kinds are both
listed, including explicit NEVER VISITED rows. Legacy blacksmith/arcanist rooms
are not generated by the current new-run generator.

## Chosen defaults (tool-only)

- Headless clock scale 8, matching `fight_soak`; maximum 120 FPS; eight settling frames.
- Per-seed wall watchdog 4,500 seconds; coordinator polling interval one second.
- Debug/proof viewport 1920 × 1080. No renderer capture or windowed command.
- Movement preference uses Manhattan distance, retaining uniform sampling among
  eligible decisions. Decision counters count dispatches, including card selection
  and target selection, rather than inferred engine mutations.
- First entry in each endpoint section is used for the requested leak comparison.
- Fresh progression, settings, recent-event history, saves, analytics and runner
  HOME per seed, so replay does not depend on another seed's profile.

No design placeholders are required. No full suite or default-group test is added.
