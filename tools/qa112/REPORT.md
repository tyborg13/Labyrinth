# QA-112 · Player-facing text consistency

Audited `codex/release` at `a869b8ba32c99e3d9a7030fa64ef6d38789b44be`. In a generated depth-20 Zekarion fight, the live objective read **111/111 HP**. The same spelling appears in enemy inspection, terrain inspection, Empower costs, healing rewards and the Continue card. The glossary title is **Health**. The fixture confirms the wording in the brief at the Health value generated by this release checkout.

[Variant counts](variants.tsv) and [all matching locations](locations.tsv) are ordered by earliest exposure. [Full inventory](inventory.tsv.gz) includes the exact source text, the formatted or observed text, a plain-text scan view, and provenance. In the location ledger, a bracketed number after a location is the occurrence count there. The four counts in this report are **JSON data / source code and scenes / production-formatted catalog / observed controls**. They count occurrences in each evidence set. A shared string can occur in several sets or on several fixture screens. Source counts include conditional copy and candidates that need a reachability check.

## Coverage and verification

- The lexical pass covered top-level `data/*.json`, recursive GDScript sources, scene text properties and the project display name. It records exact source lines and JSON pointers. The audit includes source templates and candidate literals for code-drawn and conditional copy. A source occurrence alone cannot prove that a player reaches it.
- The production formatter pass covered base card rows and tooltips, shared action/status tooltips, live relic definitions, Grimoire paragraphs, authored intent rows, opening boon variants from three seeds and the map room-label catalog. Raw Lob marking actions require a live aiming forecast to acquire damage and were skipped in the catalog pass. The existing scene probe samples live intent and trait text. Upgrades, arbitrary item and relic combinations, input modality changes, all live intent states, and unvisited run branches are represented by reachable source templates where found. Their concrete runtime permutations were outside the sample.
- The scene pass exercised 28 existing fixtures. The separate probe read the production objective labels in the first reachable fight for three seeds and a generated Zekarion arena. It read the event views for all 45 event definitions with starter and equipped/funded profiles, plus each choice available in those profiles. Code-drawn strings, clipped text, overlay occlusion, input-specific runtime changes and actual visual placement require visual inspection or additional fixtures. This run used headless text extraction.
- The dictionary is the system `/usr/share/dict/web2`, with simple suffix handling and the [game-term and common-word allowlist](spelling_allowlist.txt). Terminology counts keep exact case. Markup cleanup recognizes registered UI markup and leaves unresolved token syntax available to the leak scan. UI case is inferred for eligible multiword labels and headings. Lexical matches can include a source fragment, a grammatical variant, intentional spacing or a homograph. Rank measures when the containing surface appears.
- Existing scene probe yielded `TEXT AUDIT CAPTURE HEADLESS VALIDATION RESULT: PASS (28 fixtures)`. Final production export yielded `QA112 EVENT PAGES: 90 choice pages, 236 result pages` and `QA112 COPY EXPORT: 6141 records, 3 seeded combats, 1 Zekarion fixture`.
